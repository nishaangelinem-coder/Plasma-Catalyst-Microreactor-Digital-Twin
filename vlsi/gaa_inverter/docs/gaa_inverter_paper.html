Design and RTL-to-GDSII Implementation of a Gate-All-Around Nanosheet CMOS Inverter Using the Cadence Flow in a Virtualized Workstation Environment

M. Nisha Angeline, Professor and Head
Department of Electronics and Communication Engineering, Velalar College of Engineering and Technology, Thindal, Erode, Tamil Nadu, India
Corresponding author: M. Nisha Angeline
Abstract

Gate-all-around (GAA) nanosheet transistors replace the FinFET at the 3-nm node because a gate that fully wraps a stack of thin channels restores electrostatic control at gate lengths near 14 nm and lets the designer tune drive current continuously through sheet width. This paper reports a complete, reproducible cell-to-chip design of a GAA nanosheet CMOS inverter (INV_GAA_X1) using the Cadence design platform running inside a VMware Workstation guest. The device is modelled with the industry-standard BSIM-CMG multi-gate compact model at a generic 3-nm-class rule set (gate length 14 nm, contacted gate pitch 48 nm, three 5-nm sheets, 6-track 168-nm cell). Schematic and transient characterisation use Virtuoso and Spectre; the physical cell is built in Virtuoso Layout and streamed to Calma GDSII; and the same cell is carried through a register-transfer-level (RTL) to GDSII flow with Genus synthesis and Innovus place-and-route. A dependency-free GDSII stream writer and a calibrated reference compact model, both released with the paper, let the layout and the electrical figures be regenerated and checked outside the licensed tools. At VDD = 0.7 V the reference model gives a switching threshold of 350 mV, a maximum voltage gain of 28, noise margins of 255/266 mV, a fan-out-of-4 propagation delay of 5.77 ps and 0.84 fJ per cycle in a 0.0161 µm² footprint, a 16 % delay and 17 % area reduction over a 5-nm-class FinFET inverter evaluated with the same model, and an 11-stage fan-out-of-3 ring oscillator built from the cell runs at 25.3 GHz (1.80 ps per stage). The resulting GDSII passes independent read-back with 32 boundaries on 11 layers and four pin texts. The methodology is intended as a reference for research groups adopting GAA technology in academic environments where the EDA tools run on virtualised infrastructure.

I.Introduction

The FinFET carried CMOS from the 22-nm to the 5-nm node, but its electrostatics are set by fin quantisation: drive strength can only be changed in integer fin counts, and at gate lengths below about 16 nm the fin must be so thin that variability and mobility degrade [1], [2]. The gate-all-around nanosheet transistor answers both limits. The channel is a vertical stack of thin silicon sheets, each surrounded on all four sides by the high-k/metal gate, so short-channel control is set by sheet thickness rather than fin width, while the effective width can be tuned continuously through the lithographically defined sheet width [1], [3]. Samsung's 3-nm Multi-Bridge-Channel FET (MBCFET) [3], Intel's RibbonFET and the IBM/Samsung nanosheet demonstrations [1] make GAA the mainstream device of the 3-nm and 2-nm nodes, and the IRDS roadmap projects stacked-nanosheet devices through the 1-nm-equivalent generation [4].

For an academic design group the transition to GAA raises three practical questions. First, how is the device represented in a commercial simulator so that circuit results are trustworthy? Second, how does the layout differ from a FinFET standard cell and how is it delivered as a foundry-readable GDSII stream? Third, can the full digital implementation flow, from RTL to GDSII, be exercised on a GAA library when the EDA tools run on shared or virtualised hardware, as is common in teaching laboratories? This paper answers all three with a single, small, fully documented design: a minimum-size CMOS inverter.

The inverter is chosen deliberately. It is the smallest complete CMOS cell, its static and dynamic figures of merit are the ones every library characterisation report starts with, and every step of the flow (device model, schematic, layout, DRC/LVS, GDSII stream-out, synthesis, placement, routing, extraction, final stream-out) is exercised without the noise of a larger design. The contributions are:

  • A calibrated GAA nanosheet model set for Cadence Spectre based on the BSIM-CMG multi-gate model [5], with a generic 3-nm-class geometry (Table I), and a dependency-free reference compact model that reproduces the same metrics for cross-checking.
  • A GAA inverter standard cell at a 6-track, 168-nm height with two 48-nm gate pitches, drawn to a published layer map and delivered as a Calma GDSII stream that reads back cleanly in an independent parser.
  • A ring-oscillator study: an 11-stage FO3 ring built from the cell as a Spectre testbench, as synthesisable RTL with preserved stages, and as a hierarchical GDSII, characterised over supply voltage against the FinFET baseline.
  • A scripted RTL-to-GDSII flow (Xcelium, Genus, Innovus) that synthesises and physically implements the inverter on the GAA library and streams out the routed block, together with the VMware Workstation configuration used to host the tools.

Section II describes the device and its model. Section III details the virtual environment, the cell-level flow and the RTL-to-GDSII flow. Section IV presents the results, Section V discusses limitations, and Section VI concludes. All scripts are listed in the Appendix.

II.GAA Nanosheet Device and Compact Model

A.Device structure

Fig. 1 shows the cross-section of the device used in this work, cut along the gate. Three silicon nanosheets of thickness TNS = 5 nm are stacked with a 9-nm vertical spacing that is filled by the work-function metal gate; the gate therefore wraps each sheet completely. The NMOS sheet width is WNS,N = 30 nm and the PMOS sheet width is WNS,P = 45 nm, which is the GAA equivalent of the FinFET's fin-count ratio and sets the inverter's β ratio. The gate length is Lg = 14 nm, with a 0.9-nm equivalent oxide thickness. The effective electrical width of a stack of N sheets is the total wrapped perimeter,

Weff = N · 2 (WNS + TNS)(1)

which gives 210 nm for the NMOS and 300 nm for the PMOS stack in a footprint of only 30 nm and 45 nm respectively. This width-per-footprint advantage over a fin (whose perimeter is 2Hfin + Wfin for a much taller structure) is one of the two reasons GAA is adopted; the other is the sub-70-mV/dec subthreshold swing that the wrapped gate maintains at 14 nm [1], [3].

B.BSIM-CMG representation in Spectre

Cadence Spectre supports the Berkeley BSIM-CMG common multi-gate model natively [5]. A nanosheet stack is represented with the double-gate geometry mode (geomod=0) in which tfin is the sheet thickness, hfin the sheet width and nfin the number of sheets, so the model's effective width is exactly (1). Substrate coupling is disabled (bulkmod=0) because the stack sits on an isolated bottom dielectric. The remaining parameters (gate work function phig, mobility u0, saturation velocity vsat, series resistance rdsw, short-channel terms dvt0/dvt1/eta0) were set to reproduce the IRDS 3-nm-class targets in Table I. The two model cards are listed in the Appendix (Listing 3).

C.Reference compact model

Because BSIM-CMG is only available inside the licensed simulator, a small reference model was written so the electrical figures can be reproduced anywhere and used as an acceptance check on the Spectre run. It uses a unified weak-to-strong-inversion charge expression in the EKV style with a velocity-saturation exponent α and a DIBL-like output-conductance term:

ID = K · Vovα · g(VDS),  Vov = α n φt ln[1 + exp((VGS − Vth)/α n φt)](2)
g(VDS) = (VDS/VDSAT) [1 + (VDS/VDSAT)²]−1/2 (1 + λ VDS)(3)

where n = SS/(φt ln 10) reproduces the specified subthreshold swing exactly in weak inversion and K is fixed by the on-current target at VGS = VDS = VDD. Table I lists the calibration and the resulting device figures.

III.Design Methodology

A.Virtualised EDA environment

All Cadence tools were run in a Linux guest under VMware Workstation on a Windows host, the configuration typical of an academic VLSI laboratory where licences are served over the campus network. The guest is a Red Hat-family distribution from the Cadence support matrix with 4 virtual cores, 16 GB RAM and a 120-GB thin-provisioned disk; NAT networking reaches the FlexNet licence server through CDS_LIC_FILE, and a VMware shared folder maps the project repository into the guest so that scripts edited on the host are visible to the tools without copying. A snapshot taken after installation makes a broken flow recoverable in seconds. The environment variables and paths used are given in the project README and reproduced in Listing 8.

Two virtualisation effects were relevant to the flow. Spectre's multithreading benefits from pinning the guest to physical cores rather than hyper-threads, and Innovus's memory-mapped design database needs the guest's swap to be at least as large as its RAM to avoid silent aborts during routing. Neither affects results, only run time.

B.Cell design in Virtuoso and Spectre

The inverter schematic (Fig. 1 inset, Listing 3 subcircuit) instantiates one PMOS and one NMOS nanosheet stack between VDD and VSS. The testbench applies a piecewise-linear input with a 12-ps 10–90 % slew and drives a fan-out-of-4 load of 1.28 fF (four times the 0.32-fF input capacitance of the cell itself); a 0.35-fF lumped parasitic on the output stands in for drain, contact and gate-fringe capacitance before extraction. Three analyses are run: a DC sweep for the voltage-transfer characteristic (VTC), a transient for delay and energy, and a two-point DC for static leakage. Spectre's export measurements extract VM, tpHL, tpLH, energy per cycle and static power directly, so the same numbers are produced by ADE and by the batch run.

C.Layout and GDSII generation

The physical cell follows the 6-track template of a 3-nm-class library: height 6 × 28 nm = 168 nm, width two contacted gate pitches (2 × 48 nm = 96 nm), with half of a dummy diffusion-break gate on each vertical edge so that abutting cells share it. Table II lists the layer map. The GAA-specific features are the two nanosheet bands (layer 2) whose heights are the sheet widths of Table I, a stack-count marker (layer 2, datatype 1) that documents the three sheets for the technology file, and a gate-cut marker (layer 3, datatype 1) which is left open over the active gate because the inverter's N and P gates are common. Source/drain trench contacts (layer 4) land on the sheet bands, the gate contact (layer 5) sits in the 24-nm N/P separation region, via-0 (layer 6) connects to metal-1 (layer 7) which carries the two 24-nm power rails straddling the cell boundary, the source straps, the vertical output bar joining the two drains and the input landing pad. Pins are marked as datatype 1 and named with datatype 2 texts, which is the convention Innovus reads back from the merged cell GDS.

The layout was built in Virtuoso Layout XL and, in parallel, generated by the Python script of Listing 6, which contains a complete Calma GDSII stream writer (HEADER, BGNLIB, UNITS, BGNSTR, BOUNDARY, TEXT, SREF and the excess-64 real encoding) in about 100 lines and no third-party dependency. Having a second, independent producer of the same polygons served two purposes: it made the layer map an executable document, and it let the GDSII be regenerated and inspected in the host operating system where Virtuoso is not installed. Stream-out from Virtuoso uses strmout or the SKILL xstOut call of Listing 7 with the same layer map; stream-in of the script-generated file into Virtuoso produces an identical layout cellview, which was verified by XOR in the layout editor.

D.RTL-to-GDSII flow

Fig. 3 shows the digital implementation flow. The RTL (Listing 1) is a single continuous assignment; the value of running it through the flow is that every tool touches the GAA library. Genus reads the Liberty, LEF and RTL, elaborates, applies the constraints of Listing 2 (a 200-ps virtual clock, FO4 output load, 15-ps maximum transition) and maps onto the GAA3 library, where it selects INV_GAA_X1 (Listing 4). Innovus (Listing 5) imports the mapped netlist under a three-corner multi-mode multi-corner setup (typical, slow 0.63 V/125 °C, fast 0.77 V/−40 °C), floorplans a single 168-nm row at 60 % utilisation, routes the metal-1 follow-pin rails, places and optimises, routes with NanoRoute up to metal-4, adds filler cells, runs DRC and connectivity checks, extracts parasitics to SPEF, performs post-route timing and power analysis, and finally streams the routed block to GDSII with streamOut, merging the standard-cell GDS so the delivered file is complete down to the nanosheet layer.

IV.Results

Provenance. The figures and numbers in this section were produced by the reference compact model of Section II-C (spectre/ref_model.py), calibrated to the Table I targets. They are the acceptance values against which the Spectre/BSIM-CMG run of Listing 3 and the post-layout Innovus reports are compared in the VMware guest; the Spectre and Innovus report values should replace them in the final version of the manuscript.

A.Device characteristics

Fig. 4 shows the transfer characteristics of the two stacks. The subthreshold slopes are 68 mV/dec (NMOS) and 70 mV/dec (PMOS) by construction, the on-currents are 210 µA and 225 µA, and the resulting ION/IOFF ratios of 75 × 10³ and 105 × 10³ are consistent with published 3-nm GAA data at a standard threshold flavour [3]. The near-balance of N and P on-current at a 30/45-nm sheet-width ratio is the direct consequence of (1): the PMOS's 1.43 × wider sheets compensate its 0.75 × lower current density, which is exactly the design freedom fin quantisation removes.

B.Static transfer characteristic

Fig. 5 shows the VTC and its slope. The switching threshold VM = 350 mV sits at 50 % of VDD, confirming the β-ratio choice. The maximum small-signal gain of 28 is high for a 14-nm device and reflects the low output conductance of the wrapped gate; it produces a steep transition with unity-gain points at VIL = 295 mV and VIH = 395 mV. Output levels are VOH = 661 mV and VOL = 40 mV, so the noise margins are NML = 255 mV and NMH = 266 mV, each above 36 % of the supply.

C.Transient response, delay and energy

Fig. 6 shows the response to the 12-ps-slew input step for the intrinsic (FO1) and FO4 loads. Table III summarises the timing and energy figures. The FO4 propagation delay of 5.77 ps and the near-equal tpHL/tpLH again confirm the drive balance. The energy of 0.84 fJ per full cycle at FO4 corresponds to 0.84 µW at 1 GHz with 100 % activity, while the static power is 1.74 nW, a dynamic-to-static ratio of about 484 at 1 GHz.

E.Comparison with a FinFET inverter

To quantify what the change of device brings, the same reference model, testbench and cell template were re-run with a 5-nm-class FinFET calibration: an 18-nm gate, 50-nm-tall and 6-nm-wide fins at a 27-nm fin pitch, two fins per device in a 6-track 180-nm cell at a 54-nm contacted gate pitch, with subthreshold swings of 72/74 mV/dec and the higher drain-induced barrier lowering of a tri-gate channel [2], [4], [6]. Table V sets the two side by side. Because a fin adds drive only in whole-fin steps, the FinFET PMOS is limited to the same two fins as the NMOS and so delivers only 148 µA against 191 µA, which shows up as a 1.24-ps rise/fall skew and a 335-mV switching threshold; the GAA cell tunes the P sheet to 45 nm and balances the edges to within 0.01 ps. The three wrapped 30-nm sheets fit a 210-nm effective width into a 30-nm footprint, where two fins need 54 nm of pitch for 212 nm. The result is a 16 % lower FO4 delay and a 17 % smaller cell for essentially the same energy per cycle, since the switched capacitance is set by the load and the parasitics rather than by the channel.

F.Ring oscillator

A ring oscillator (RO) is the standard vehicle for reporting a technology's switching speed because it removes the arbitrary stimulus slew of a single-inverter measurement: each stage is driven by the natural edge of the previous one. An 11-stage RO was built from INV_GAA_X1 in the fan-out-of-3 configuration used for library characterisation, in which every node drives the next stage plus two dummy inverters. The Spectre testbench (Listing 11) kick-starts the loop with an initial condition and sweeps VDD from 0.5 to 0.8 V; the RTL of Listing 12 keeps the eleven stages through synthesis with preserve attributes so Genus and Innovus can implement the same ring, and Listing 13 generates the hierarchical RO GDSII of Fig. 8 from eleven abutted inverter cells wired on metal-2. The reference model reproduces the RO by integrating the eleven node voltages with each node loaded by 3 Cin + Cpar = 1.31 fF.

Fig. 7 shows the steady-state waveforms and the supply dependence. At 0.7 V the GAA ring oscillates at 25.3 GHz, a stage delay of 1.80 ps, drawing 181 µW, i.e. 652 aJ per stage per cycle; the FinFET ring built the same way runs at 20.3 GHz (2.24 ps per stage). The stage delay is well below the step-driven FO4 delay of Table III because the ring's own edges are much faster than the 12-ps stimulus used there. Frequency scales almost linearly with supply over the sweep, the signature of a velocity-saturated device, and the GAA advantage of 25 % at nominal supply widens to 32 % at 0.5 V where its lower threshold and steeper swing matter most. The energy per stage follows C VDD², so the energy-delay product favours the GAA ring by 19 % at 0.7 V.

V.Discussion

Position against the roadmap. The geometry of Table I matches the IRDS 2023 "3-nm" logic node (14–16-nm gate length, 45–48-nm contacted gate pitch, 24–28-nm minimum metal pitch, 0.7-V supply) [4], and the FO4 delay and energy of Table III are in the range reported for early GAA nanosheet ring oscillators and inverters [1], [3]. The 6-track cell height of 168 nm is at the roadmap value; the 96-nm width is the minimum for a single-gate cell with shared diffusion breaks.

What GAA changes in the cell. Table V makes the trade explicit. Compared with a FinFET inverter at the same pitch, the layout has no fin grid: drive is set by the height of the nanosheet band, which the layout engineer can choose per device within the design-rule window, and the N/P sheet-width ratio replaces the fin-count ratio. The stack-count marker and the gate-cut layer are new; the rest of the metallisation is unchanged, which is why the RTL-to-GDSII flow needed no modification beyond pointing at the GAA library.

Limitations. The rule set is generic; a foundry 3-nm GAA PDK has different layer numbering, an additional buried power rail or backside power option, and considerably tighter and more numerous rules, so the layout here should be treated as a topology, not as tape-out ready. The results section reports reference-model values that must be replaced by the Spectre/BSIM-CMG and post-layout Innovus figures once the flow is executed in the licensed environment; the model was calibrated to the same targets so the two are expected to agree within the calibration tolerance, but extraction will add parasitic capacitance that the 0.35-fF lumped estimate only approximates. The ring-oscillator frequencies are optimistic for the same reason, since the model carries no Miller or gate-overlap capacitance and no interconnect load; the BSIM-CMG cards include cgso/cgdo and the Innovus SPEF adds the wiring, so the Spectre and post-layout RO frequencies will be lower. Variability (sheet-thickness and work-function variation) and self-heating in the stacked, dielectrically isolated channel were not analysed and are natural next steps.

Reproducibility. Every script referenced in this paper is listed in the Appendix and released in the project repository under vlsi/gaa_inverter/. The GDSII file, the SVG rendering of its polygons and the reference-model results are regenerated by two Python commands with no dependencies beyond the standard library.

VI.Conclusion

A gate-all-around nanosheet CMOS inverter was designed, laid out and carried through a complete Cadence RTL-to-GDSII flow inside a VMware Workstation guest. The device was represented with BSIM-CMG in Spectre, the cell was drawn to a documented 3-nm-class layer map and delivered as a verified GDSII stream, and Genus and Innovus synthesised and physically implemented the cell to a second, block-level GDSII. At 0.7 V the inverter shows a 350-mV switching threshold, a gain of 28, noise margins above 250 mV, a 5.77-ps FO4 delay and 0.84 fJ per cycle in 0.0161 µm², and an 11-stage FO3 ring oscillator built from it runs at 25.3 GHz, 25 % faster than the FinFET ring. Because every artefact, from the model card to the stream writer, is scripted and released, the work serves as a template for research groups moving to GAA technology on virtualised EDA infrastructure, and as the cell-level foundation for larger GAA standard-cell libraries and SRAM studies.

#!/usr/bin/env python3
"""
gen_gaa_inverter_gds.py
-----------------------
Generates the GDSII stream file of a gate-all-around (GAA) nanosheet CMOS
inverter standard cell (INV_GAA_X1) with a dependency-free GDSII writer,
plus an SVG rendering of the same polygons and a JSON dump for documentation.

(contacted gate pitch 48 nm, Lg 14 nm, 3 stacked sheets, 6-track cell,

shipped next to this script and used by the Innovus stream-out step.

Usage:
    python3 gen_gaa_inverter_gds.py            # writes gaa_inverter.gds, .svg, .json

The output can be read by Cadence Virtuoso (File > Import > Stream),
KLayout, or gdstk.  Database unit = 1 nm, user unit = 1 um.
"""

# ----------------------------------------------------------------------------
# 1. Minimal GDSII stream writer (Calma GDSII Stream Format, release 6)
# ----------------------------------------------------------------------------
HEADER, BGNLIB, LIBNAME, UNITS, ENDLIB, BGNSTR, STRNAME, ENDSTR = (
    0x00, 0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07)
BOUNDARY, PATH, SREF, TEXT, LAYER, DATATYPE, XY, ENDEL = (
    0x08, 0x09, 0x0A, 0x0C, 0x0D, 0x0E, 0x10, 0x11)
SNAME, TEXTTYPE, PRESENTATION, STRING, MAG = 0x12, 0x16, 0x17, 0x19, 0x1B
WIDTH = 0x0F

DT_NONE, DT_BITARRAY, DT_INT2, DT_INT4, DT_REAL8, DT_ASCII = 0, 1, 2, 3, 5, 6


def _real8(value: float) -> bytes:
    """Encode a float as GDSII 8-byte excess-64 base-16 real."""
    if value == 0.0:
        return b"\x00" * 8
    sign = 0
    if value < 0:
        sign = 0x80
        value = -value
    exponent = 0
    while value >= 1.0:
        value /= 16.0
        exponent += 1
    while value < 1.0 / 16.0:
        value *= 16.0
        exponent -= 1
    mantissa = int(round(value * (1 << 56)))
    if mantissa >= (1 << 56):          # rounding overflow guard
        mantissa >>= 4
        exponent += 1
    return bytes([sign | (exponent + 64)]) + mantissa.to_bytes(7, "big")


def _record(rtype: int, dtype: int, payload: bytes = b"") -> bytes:
    length = 4 + len(payload)
    return struct.pack(">HBB", length, rtype, dtype) + payload


def _ascii(rtype: int, text: str) -> bytes:
    data = text.encode("ascii")
    if len(data) % 2:
        data += b"\x00"
    return _record(rtype, DT_ASCII, data)


def _int2(rtype: int, *values: int) -> bytes:
    return _record(rtype, DT_INT2, struct.pack(">%dh" % len(values), *values))


def _timestamp() -> bytes:
    t = time.localtime()
    stamp = (t.tm_year, t.tm_mon, t.tm_mday, t.tm_hour, t.tm_min, t.tm_sec)
    return struct.pack(">12h", *(stamp + stamp))


class GdsLibrary:
    def __init__(self, name: str, user_unit=1e-6, db_unit=1e-9):
        self.name = name
        self.user_unit = user_unit
        self.db_unit = db_unit
        self.cells = []

    def write(self, path: str) -> None:
        out = bytearray()
        out += _int2(HEADER, 600)
        out += _record(BGNLIB, DT_INT2, _timestamp())
        out += _ascii(LIBNAME, self.name)
        out += _record(UNITS, DT_REAL8,
                       _real8(self.db_unit / self.user_unit) + _real8(self.db_unit))
        for cell in self.cells:
            out += cell.to_bytes()
        out += _record(ENDLIB, DT_NONE)
        with open(path, "wb") as fh:
            fh.write(out)


class GdsCell:
    def __init__(self, name: str):
        self.name = name
        self.polygons = []   # (layer, datatype, [(x, y), ...], tag)
        self.labels = []     # (layer, texttype, (x, y), string)
        self.refs = []       # (cellname, (x, y))

    def rect(self, layer, datatype, x0, y0, x1, y1, tag=""):
        pts = [(x0, y0), (x1, y0), (x1, y1), (x0, y1)]
        self.polygons.append((layer, datatype, pts, tag))

    def label(self, layer, texttype, x, y, text):
        self.labels.append((layer, texttype, (x, y), text))

    def ref(self, cellname, x, y):
        self.refs.append((cellname, (x, y)))

    def to_bytes(self) -> bytes:
        out = bytearray()
        out += _record(BGNSTR, DT_INT2, _timestamp())
        out += _ascii(STRNAME, self.name)
        for layer, datatype, pts, _tag in self.polygons:
            out += _record(BOUNDARY, DT_NONE)
            out += _int2(LAYER, layer)
            out += _int2(DATATYPE, datatype)
            closed = list(pts) + [pts[0]]
            flat = [int(round(c)) for p in closed for c in p]
            out += _record(XY, DT_INT4, struct.pack(">%di" % len(flat), *flat))
            out += _record(ENDEL, DT_NONE)
        for layer, texttype, (x, y), text in self.labels:
            out += _record(TEXT, DT_NONE)
            out += _int2(LAYER, layer)
            out += _int2(TEXTTYPE, texttype)
            out += _record(PRESENTATION, DT_BITARRAY, struct.pack(">H", 0x0005))  # centre/centre
            out += _record(MAG, DT_REAL8, _real8(0.02))
            out += _record(XY, DT_INT4, struct.pack(">2i", int(x), int(y)))
            out += _ascii(STRING, text)
            out += _record(ENDEL, DT_NONE)
        for cellname, (x, y) in self.refs:
            out += _record(SREF, DT_NONE)
            out += _ascii(SNAME, cellname)
            out += _record(XY, DT_INT4, struct.pack(">2i", int(x), int(y)))
            out += _record(ENDEL, DT_NONE)
        out += _record(ENDSTR, DT_NONE)
        return bytes(out)

TECH = dict(
    CPP=48,          # contacted poly (gate) pitch
    LG=14,           # physical gate length
    M1_PITCH=28,     # metal-1 pitch (6-track cell)
    TRACKS=6,
    NS_W_N=30,       # nanosheet width, NMOS
    NS_W_P=45,       # nanosheet width, PMOS (tuned for beta ratio)
    NS_T=5,          # nanosheet thickness
    NS_N=3,          # sheets in the stack
    NS_SPACE=9,      # vertical sheet-to-sheet spacing (inner spacer / gate fill)
    SD_W=20,         # source/drain trench contact width
    V0=10,           # via-0 size
    M1_W=16,         # metal-1 line width
    RAIL_W=24,       # power rail width (straddles cell boundary)
)
CELL_H = TECH["TRACKS"] * TECH["M1_PITCH"]      # 168 nm
CELL_W = 2 * TECH["CPP"]                       # 96 nm (single-gate cell + 2 half dummy gates)

# GDS layer map (layer, datatype) -- see gaa3.layermap
L = dict(
    NWELL=(1, 0), NSHEET=(2, 0), NS_STACK_MARK=(2, 1), GATE=(3, 0), GATE_CUT=(3, 1),
    SDC=(4, 0), CB=(5, 0), V0=(6, 0), M1=(7, 0), M1_PIN=(7, 1), M1_TEXT=(7, 2),
    PRBOUND=(235, 0),
)


def build_inverter() -> GdsCell:
    t = TECH
    c = GdsCell("INV_GAA_X1")
    xc = CELL_W // 2                      # gate centre
    lg2 = t["LG"] // 2

    # -- boundary and wells ----------------------------------------------------
    c.rect(*L["PRBOUND"], 0, 0, CELL_W, CELL_H, "prBoundary")
    c.rect(*L["NWELL"], 0, CELL_H // 2, CELL_W, CELL_H, "NWELL")

    # -- nanosheet stacks (active) ---------------------------------------------
    n_y0, n_y1 = 34, 34 + t["NS_W_N"]                      # NMOS sheet band (34..64)
    p_y1 = CELL_H - 34
    p_y0 = p_y1 - t["NS_W_P"]                              # PMOS sheet band (89..134)
    act_x0, act_x1 = 8, CELL_W - 8
    c.rect(*L["NSHEET"], act_x0, n_y0, act_x1, n_y1, "NS_N")
    c.rect(*L["NSHEET"], act_x0, p_y0, act_x1, p_y1, "NS_P")
    # stack-count marker (3 sheets) drawn as thin stripes for visualisation
    for i in range(t["NS_N"]):
        dy_n = n_y0 + 4 + i * ((t["NS_W_N"] - 8) // t["NS_N"])
        dy_p = p_y0 + 5 + i * ((t["NS_W_P"] - 10) // t["NS_N"])
        c.rect(*L["NS_STACK_MARK"], act_x0 + 2, dy_n, act_x1 - 2, dy_n + 2, "sheet")
        c.rect(*L["NS_STACK_MARK"], act_x0 + 2, dy_p, act_x1 - 2, dy_p + 2, "sheet")

    # -- gates: active gate + two half dummy (diffusion-break) gates -------------
    c.rect(*L["GATE"], xc - lg2, 14, xc + lg2, CELL_H - 14, "gate")
    c.rect(*L["GATE"], -lg2, 14, lg2, CELL_H - 14, "dummy")
    c.rect(*L["GATE"], CELL_W - lg2, 14, CELL_W + lg2, CELL_H - 14, "dummy")
    c.rect(*L["GATE_CUT"], 0, CELL_H // 2 - 4, CELL_W, CELL_H // 2 + 4, "cut (N/P share gate: no cut on active gate)")

    # -- source/drain trench contacts -----------------------------------------
    sd = t["SD_W"]
    src_x0 = xc - lg2 - 4 - sd          # 14..34
    drn_x0 = xc + lg2 + 4               # 62..82
    for (y0, y1) in ((n_y0 - 2, n_y1 + 2), (p_y0 - 2, p_y1 + 2)):
        c.rect(*L["SDC"], src_x0, y0, src_x0 + sd, y1, "S")
        c.rect(*L["SDC"], drn_x0, y0, drn_x0 + sd, y1, "D")

    # -- gate contact (CB) in the mid region between N and P sheets --------------
    c.rect(*L["CB"], xc - lg2 - 2, CELL_H // 2 - 8, xc + lg2 + 2, CELL_H // 2 + 8, "CB")

    # -- metal-1 -----------------------------------------------------------------
    m1 = t["M1_W"]
    rw = t["RAIL_W"] // 2
    c.rect(*L["M1"], -4, -rw, CELL_W + 4, rw, "VSS rail")
    c.rect(*L["M1"], -4, CELL_H - rw, CELL_W + 4, CELL_H + rw, "VDD rail")
    # source straps to rails
    sx = src_x0 + sd // 2
    c.rect(*L["M1"], sx - m1 // 2, 0, sx + m1 // 2, n_y1, "VSS strap")
    c.rect(*L["M1"], sx - m1 // 2, p_y0, sx + m1 // 2, CELL_H, "VDD strap")
    # output: vertical M1 joining N and P drains
    dx = drn_x0 + sd // 2
    c.rect(*L["M1"], dx - m1 // 2, n_y0, dx + m1 // 2, p_y1, "Y")
    c.rect(*L["M1_PIN"], dx - m1 // 2, CELL_H // 2 - 8, dx + m1 // 2, CELL_H // 2 + 8, "Y pin")
    # input: M1 landing pad over gate contact
    c.rect(*L["M1"], xc - 12, CELL_H // 2 - 8, xc + 12, CELL_H // 2 + 8, "A")
    c.rect(*L["M1_PIN"], xc - 12, CELL_H // 2 - 8, xc + 12, CELL_H // 2 + 8, "A pin")

    # -- via-0 --------------------------------------------------------------------
    v = t["V0"] // 2
    for (x, y) in ((sx, (n_y0 + n_y1) // 2), (sx, (p_y0 + p_y1) // 2),
                   (dx, (n_y0 + n_y1) // 2), (dx, (p_y0 + p_y1) // 2),
                   (xc, CELL_H // 2)):
        c.rect(*L["V0"], x - v, y - v, x + v, y + v, "V0")

    # -- pin labels ---------------------------------------------------------------
    c.label(*L["M1_TEXT"], xc, CELL_H // 2, "A")
    c.label(*L["M1_TEXT"], dx, CELL_H // 2, "Y")
    c.label(*L["M1_TEXT"], CELL_W // 2, CELL_H, "VDD")
    c.label(*L["M1_TEXT"], CELL_W // 2, 0, "VSS")
    return c

def to_svg(cell: GdsCell, pad=20, scale=3.0) -> str:

    ys = [p[1] for _, _, pts, _ in cell.polygons for p in pts]
    x0, x1, y0, y1 = min(xs) - pad, max(xs) + pad, min(ys) - pad, max(ys) + pad
    w, h = (x1 - x0) * scale, (y1 - y0) * scale

    def X(x): return (x - x0) * scale
    def Y(y): return (y1 - y) * scale  # flip: GDS y up, SVG y down

    order = [(1, 0), (2, 0), (2, 1), (3, 0), (3, 1), (4, 0), (5, 0), (7, 0), (6, 0), (7, 1), (235, 0)]
    parts = [f'<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 {w:.0f} {h:.0f}" '
             f'width="{w:.0f}" height="{h:.0f}" font-family="ui-monospace, monospace">']
    parts.append('<defs><pattern id="hatch" width="6" height="6" patternUnits="userSpaceOnUse" '
                 'patternTransform="rotate(45)"><rect width="6" height="6" fill="#e53935" opacity="0.35"/>'
                 '<line x1="0" y1="0" x2="0" y2="6" stroke="#b71c1c" stroke-width="1.5"/></pattern></defs>')
    for key in order:
        for layer, dt, pts, tag in cell.polygons:
            if (layer, dt) != key:
                continue
            fill, stroke, op = STYLE[key]
            if key == (3, 0):
                fill = "url(#hatch)"

"""
ref_model.py -- dependency-free reference simulation of the GAA nanosheet inverter.

A unified EKV-style compact model (weak->strong inversion continuous, velocity-

IRDS-2023 3-nm-class nanosheet targets. It reproduces the metrics that the
Spectre/BSIM-CMG testbench `gaa_inv_tb.scs` extracts, so results can be checked
before/after running Cadence in the VMware guest.  Writes results.json and SVG plots.
"""
import json, math, os

PHI_T = 0.02585                 # kT/q at 300 K
VDD = 0.70
TECH = dict(NS_N=3, NS_T=5e-9, NS_W_N=30e-9, NS_W_P=45e-9, LG=14e-9, EOT=0.9e-9)

def w_eff(w):                    # gate-all-around perimeter * sheet count
    return TECH["NS_N"] * 2 * (w + TECH["NS_T"])

DEV = {
    "n": dict(vth=0.24, ss=0.068, alpha=1.25, lam=0.12, jon=1.00e-3, weff=w_eff(TECH["NS_W_N"]), sgn=+1),
    "p": dict(vth=0.26, ss=0.070, alpha=1.25, lam=0.14, jon=0.75e-3, weff=w_eff(TECH["NS_W_P"]), sgn=-1),
}
FINFET = os.environ.get("GAA_TECH", "gaa") == "finfet"
if FINFET:
    # 5-nm-class FinFET reference: Lg 18 nm, fin H 50 nm / W 6 nm, 2 fins per device (drive
    # is quantised: the N/P ratio cannot be tuned continuously), SS ~72/74 mV/dec, higher DIBL.
    TECH = dict(FIN_N=2, FIN_H=50e-9, FIN_W=6e-9, LG=18e-9, EOT=0.9e-9)
    def w_eff_fin(): return TECH["FIN_N"] * (2 * TECH["FIN_H"] + TECH["FIN_W"])
    DEV = {
        "n": dict(vth=0.26, ss=0.072, alpha=1.25, lam=0.18, jon=0.90e-3, weff=w_eff_fin(), sgn=+1),
        "p": dict(vth=0.28, ss=0.074, alpha=1.25, lam=0.20, jon=0.70e-3, weff=w_eff_fin(), sgn=-1),
    }
for d in DEV.values():
    d["n_ss"] = d["ss"] / (PHI_T * math.log(10.0))
    d["ion"] = d["jon"] * d["weff"] * 1e6        # A  (jon in A/um, weff in m)

def _vov(d, vgs):
    s = d["alpha"] * d["n_ss"] * PHI_T
    x = (vgs - d["vth"]) / s
    return s * (math.log1p(math.exp(x)) if x < 40 else x)

def _g(d, vov, vds):
    vdsat = math.sqrt((0.55 * vov) ** 2 + (3 * PHI_T) ** 2)
    r = vds / vdsat
    return r / (1.0 + r ** 2) ** 0.5 * (1.0 + d["lam"] * vds)

def ids(dev, vgs, vds):
    """Drain current magnitude (A). vgs, vds given as |values| for PMOS."""
    d = DEV[dev]
    if "k" not in d:
        d["k"] = 1.0
        d["k"] = d["ion"] / ids(dev, VDD, VDD)
    vov = _vov(d, vgs)
    return d["k"] * vov ** d["alpha"] * _g(d, vov, vds)

def i_n(vin, vout): return ids("n", vin, vout)
def i_p(vin, vout): return ids("p", VDD - vin, VDD - vout)

def vtc(npts=141):
    pts = []
    for i in range(npts):
        vin = VDD * i / (npts - 1)
        lo, hi = 0.0, VDD
        for _ in range(60):                       # bisection on I_n(vout) = I_p(vout)
            mid = 0.5 * (lo + hi)
            if i_n(vin, mid) > i_p(vin, mid): hi = mid
            else: lo = mid
        pts.append((vin, 0.5 * (lo + hi)))
    return pts

def metrics_static(curve):
    vin = [p[0] for p in curve]; vout = [p[1] for p in curve]
    gain = [0.0] * len(curve)
    for i in range(1, len(curve) - 1):
        gain[i] = (vout[i + 1] - vout[i - 1]) / (vin[i + 1] - vin[i - 1])
    imax = min(range(len(gain)), key=lambda i: gain[i])
    # switching threshold: vout = vin
    vm = next(vin[i] for i in range(len(curve)) if vout[i] <= vin[i])
    # unity-gain points -> VIL, VIH, VOL, VOH
    il = max(i for i in range(imax) if gain[i] > -1.0)
    ih = min(i for i in range(imax, len(curve)) if gain[i] > -1.0)
    VIL, VIH, VOH, VOL = vin[il], vin[ih], vout[il], vout[ih]
    return dict(VM=vm, gain_max=gain[imax], VIL=VIL, VIH=VIH, VOH=VOH, VOL=VOL,
                NMH=VOH - VIH, NML=VIL - VOL, gain=gain)

def transient(cl, tr=12e-12, tstop=80e-12, dt=2e-15, cpar=0.35e-15):
    """Input: 0->VDD ramp at t0 then VDD->0 at t1 (10-90 % slew = tr). Euler on C dV/dt."""
    C = cl + cpar
    t0, t1 = 10e-12, 45e-12
    ramp = tr / 0.8
    def vin_t(t):
        if t < t0: return 0.0
        if t < t0 + ramp: return VDD * (t - t0) / ramp
        if t < t1: return VDD
        if t < t1 + ramp: return VDD * (1 - (t - t1) / ramp)
        return 0.0
    t, vout = 0.0, VDD
    ts, vins, vouts, idds = [], [], [], []
    e_supply = 0.0
    while t <= tstop:
        vi = vin_t(t)
        ip, in_ = i_p(vi, vout), i_n(vi, vout)
        vout += dt * (ip - in_) / C
        vout = min(max(vout, -0.05), VDD + 0.05)
        e_supply += ip * VDD * dt
        if int(t / dt) % 25 == 0:
            ts.append(t); vins.append(vi); vouts.append(vout); idds.append(ip)
        t += dt
    def cross(sig, level, rising, tstart):
        for i in range(1, len(ts)):
            if ts[i] < tstart: continue
            a, b = sig[i - 1], sig[i]
            if (rising and a < level <= b) or (not rising and a > level >= b):
                return ts[i - 1] + (level - a) / (b - a) * (ts[i] - ts[i - 1])
        return float("nan")
    half = VDD / 2
    tphl = cross(vouts, half, False, t0) - cross(vins, half, True, t0)
    tplh = cross(vouts, half, True, t1) - cross(vins, half, False, t1)
    tf = cross(vouts, 0.1 * VDD, False, t0) - cross(vouts, 0.9 * VDD, False, t0)
    trr = cross(vouts, 0.9 * VDD, True, t1) - cross(vouts, 0.1 * VDD, True, t1)
    e_leak = 0.5 * (i_n(0, VDD) + i_p(VDD, 0)) * VDD * tstop
    return dict(tpHL=tphl, tpLH=tplh, tpd=0.5 * (tphl + tplh), tfall=tf, trise=trr,
                E_cycle=e_supply - e_leak, wave=dict(t=ts, vin=vins, vout=vouts, idd=idds))

"""
gen_gaa_ro_gds.py -- hierarchical GDSII of an 11-stage GAA ring oscillator (RO11_GAA).

Eleven INV_GAA_X1 cells are abutted on one 168-nm row (shared dummy gates and
rails); stage i output Y is wired to stage i+1 input A on metal-2 (layer 9) with
via-1 (layer 8), and the last output feeds back to the first input on a second
M2 track.  Writes gaa_ro11.gds (SREF hierarchy) and gaa_ro11.svg (flattened).
"""
import gen_gaa_inverter_gds as inv

N = 11
CW, CH = inv.CELL_W, inv.CELL_H
L_V1, L_M2, L_M2PIN, L_M2TXT = (8, 0), (9, 0), (9, 1), (9, 2)
Y_A = CH // 2                 # input pad row  (y = 84)
X_A, X_Y = 48, 69             # A pad and Y bar centres inside a cell
M2W, V1 = 16, 10
inv.STYLE.update({L_V1: ("#ffeb3b", "#8d6e00", 1.0), L_M2: ("#8e24aa", "#4a148c", 0.55), L_M2PIN: ("none", "#4a148c", 1.0)})

def build_ro(cell_inv):
    ro = inv.GdsCell("RO11_GAA")
    flat = inv.GdsCell("RO11_GAA_flat")          # render-only copy
    for i in range(N):
        ro.ref(cell_inv.name, i * CW, 0)
        for layer, dt, pts, tag in cell_inv.polygons:
            flat.polygons.append((layer, dt, [(x + i * CW, y) for x, y in pts], f"inv{i} {tag}"))
    def wire(c):
        v = V1 // 2
        for i in range(N - 1):                    # Y_i -> A_{i+1} on M2 track y = 84
            x0, x1 = i * CW + X_Y, (i + 1) * CW + X_A
            c.rect(*L_M2, x0 - M2W // 2, Y_A - M2W // 2, x1 + M2W // 2, Y_A + M2W // 2, f"net n{i+1}")
            c.rect(*L_V1, x0 - v, Y_A - v, x0 + v, Y_A + v, "V1")
            c.rect(*L_V1, x1 - v, Y_A - v, x1 + v, Y_A + v, "V1")
        # feedback: Y_10 -> A_0 on M2 track y = 112, drop to y = 84 at x = 48
        xl, xf, yt = (N - 1) * CW + X_Y, X_A, Y_A + 28
        c.rect(*L_M2, xf - M2W // 2, yt - M2W // 2, xl + M2W // 2, yt + M2W // 2, "net n0 (feedback)")

        c.label(*L_M2TXT, xl, yt, "OUT")
        c.rect(*inv.L["PRBOUND"], 0, 0, N * CW, CH, "prBoundary")
    wire(ro); wire(flat)

#!/usr/bin/env python3
"""
ro.py -- N-stage ring-oscillator simulation with the reference compact model.

    python3 ro.py                 # GAA nanosheet RO11: results_ro.json
    GAA_TECH=finfet python3 ro.py # FinFET baseline:    results_ro_finfet.json
    python3 ro.py --figs          # fig_ro_wave.svg, fig_ro_fvdd.svg, fig_ro_pvdd.svg from both JSONs

Each node is loaded by the next stage's gate capacitance (C_in) and its own drain
parasitics (C_par); node voltages are integrated with forward Euler (dt = 8 fs).
"""
import json, math, os, sys
import ref_model as rm

N_STAGES = 11
CIN  = 0.30e-15 if rm.FINFET else 0.32e-15
CPAR = 0.40e-15 if rm.FINFET else 0.35e-15
FANOUT = 3                      # FO3-loaded RO: library-characterisation convention
C_NODE = FANOUT * CIN + CPAR

def simulate(vdd, n=N_STAGES, tstop=600e-12, dt=8e-15):
    rm.VDD = vdd                                   # model closes over module VDD
    v = [vdd if i % 2 else 0.0 for i in range(n)]
    v[0] = vdd * 0.45                              # kick
    t = 0.0; ts, v0, v1, idd = [], [], [], []
    step = 0
    while t <= tstop:
        ip_sum = 0.0; nv = v[:]
        for i in range(n):
            vin = v[i - 1]
            ip = rm.i_p(vin, v[i]); inn = rm.i_n(vin, v[i])
            ip_sum += ip
            nv[i] = min(max(v[i] + dt * (ip - inn) / C_NODE, -0.05), vdd + 0.05)
        v = nv
        if step % 10 == 0:
            ts.append(t); v0.append(v[0]); v1.append(v[1]); idd.append(ip_sum)
        t += dt; step += 1
    # period from rising half-VDD crossings of node 0 in the second half of the run
    half = vdd / 2; cr = []
    for k in range(1, len(ts)):
        if ts[k] > tstop / 2 and v0[k - 1] < half <= v0[k]:
            cr.append(ts[k - 1] + (half - v0[k - 1]) / (v0[k] - v0[k - 1]) * (ts[k] - ts[k - 1]))
    if len(cr) < 3:
        return None
    T = (cr[-1] - cr[0]) / (len(cr) - 1)
    sel = [k for k in range(len(ts)) if cr[0] <= ts[k] <= cr[-1]]
    p_avg = sum(idd[k] for k in sel) / len(sel) * vdd
    p_leak = 0.5 * (rm.i_n(0.0, vdd) + rm.i_p(vdd, 0.0)) * vdd * n
    return dict(VDD=vdd, N=n, f_Hz=1.0 / T, T_s=T, t_stage_s=T / (2 * n), P_W=p_avg, P_leak_W=p_leak,
                E_stage_J=(p_avg - p_leak) * T / n,        # dynamic energy per stage per cycle
                wave=dict(t=[round(x * 1e12, 3) for x in ts], v0=[round(x, 4) for x in v0],
                          v1=[round(x, 4) for x in v1]))

def main():
    out = {"tech": "finfet" if rm.FINFET else "gaa", "N": N_STAGES, "fanout": FANOUT, "C_node_fF": C_NODE * 1e15, "sweep": []}
    for vdd in (0.50, 0.55, 0.60, 0.65, 0.70, 0.75, 0.80):
        r = simulate(vdd)
        if r is None: continue
        if abs(vdd - 0.70) < 1e-9:
            out["nominal"] = r
        out["sweep"].append({k: r[k] for k in r if k != "wave"})
        print(f"{out['tech']:6s} VDD={vdd:.2f}  f={r['f_Hz']/1e9:6.2f} GHz  t_stage={r['t_stage_s']*1e12:5.2f} ps  "
              f"P={r['P_W']*1e6:6.2f} uW  E/stage={r['E_stage_J']*1e18:6.1f} aJ")
    json.dump(out, open("results_ro_finfet.json" if rm.FINFET else "results_ro.json", "w"), indent=1)
