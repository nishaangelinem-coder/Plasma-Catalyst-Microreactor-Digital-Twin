Design and RTL-to-GDSII Implementation of a Gate-All-Around Nanosheet CMOS Inverter Using the Cadence Flow in a Virtualized Workstation Environment

M. Nisha Angeline, Professor and Head
Department of Electronics and Communication Engineering, Velalar College of Engineering and Technology, Thindal, Erode, Tamil Nadu, India
Corresponding author: M. Nisha Angeline
Abstract

Gate-all-around (GAA) nanosheet transistors replace the FinFET at the 3-nm node because a gate that fully wraps a stack of thin channels restores electrostatic control at gate lengths near 14 nm and lets the designer tune drive current continuously through sheet width. This paper reports a complete, reproducible cell-to-chip design of a GAA nanosheet CMOS inverter (INV_GAA_X1) using the Cadence design platform running inside a VMware Workstation guest. The device is modelled with the industry-standard BSIM-CMG multi-gate compact model at a generic 3-nm-class rule set (gate length 14 nm, contacted gate pitch 48 nm, three 5-nm sheets, 6-track 168-nm cell). Schematic and transient characterisation use Virtuoso and Spectre; the physical cell is built in Virtuoso Layout and streamed to Calma GDSII; and the same cell is carried through a register-transfer-level (RTL) to GDSII flow with Genus synthesis and Innovus place-and-route. A dependency-free GDSII stream writer and a calibrated reference compact model, both released with the paper, let the layout and the electrical figures be regenerated and checked outside the licensed tools. At VDD = 0.7 V the reference model gives a switching threshold of 350 mV, a maximum voltage gain of 28, noise margins of 255/266 mV, a fan-out-of-4 propagation delay of 5.77 ps and 0.84 fJ per cycle in a 0.0161 µm² footprint, a 16 % delay and 17 % area reduction over a 5-nm-class FinFET inverter evaluated with the same model, and an 11-stage fan-out-of-3 ring oscillator built from the cell runs at 25.3 GHz (1.80 ps per stage). A NAND2 cell built with the N and P sheet widths swapped balances its series stack in a 3-pitch, 0.0242 µm² footprint with a 7.60-ps worst-case FO4 delay, and a 0.0207 µm² six-transistor SRAM bitcell whose sheet-width ratios raise the read static noise margin to 105 mV against 94 mV for a one-fin FinFET cell of the same area. The resulting GDSII passes independent read-back with 32 boundaries on 11 layers and four pin texts. The methodology is intended as a reference for research groups adopting GAA technology in academic environments where the EDA tools run on virtualised infrastructure.

I.Introduction

The FinFET carried CMOS from the 22-nm to the 5-nm node, but its electrostatics are set by fin quantisation: drive strength can only be changed in integer fin counts, and at gate lengths below about 16 nm the fin must be so thin that variability and mobility degrade [1], [2]. The gate-all-around nanosheet transistor answers both limits. The channel is a vertical stack of thin silicon sheets, each surrounded on all four sides by the high-k/metal gate, so short-channel control is set by sheet thickness rather than fin width, while the effective width can be tuned continuously through the lithographically defined sheet width [1], [3]. Samsung's 3-nm Multi-Bridge-Channel FET (MBCFET) [3], Intel's RibbonFET and the IBM/Samsung nanosheet demonstrations [1] make GAA the mainstream device of the 3-nm and 2-nm nodes, and the IRDS roadmap projects stacked-nanosheet devices through the 1-nm-equivalent generation [4].

For an academic design group the transition to GAA raises three practical questions. First, how is the device represented in a commercial simulator so that circuit results are trustworthy? Second, how does the layout differ from a FinFET standard cell and how is it delivered as a foundry-readable GDSII stream? Third, can the full digital implementation flow, from RTL to GDSII, be exercised on a GAA library when the EDA tools run on shared or virtualised hardware, as is common in teaching laboratories? This paper answers all three with a single, small, fully documented design: a minimum-size CMOS inverter.

The inverter is chosen deliberately. It is the smallest complete CMOS cell, its static and dynamic figures of merit are the ones every library characterisation report starts with, and every step of the flow (device model, schematic, layout, DRC/LVS, GDSII stream-out, synthesis, placement, routing, extraction, final stream-out) is exercised without the noise of a larger design. The contributions are:

  • A calibrated GAA nanosheet model set for Cadence Spectre based on the BSIM-CMG multi-gate model [5], with a generic 3-nm-class geometry (Table I), and a dependency-free reference compact model that reproduces the same metrics for cross-checking.
  • A GAA inverter standard cell at a 6-track, 168-nm height with two 48-nm gate pitches, drawn to a published layer map and delivered as a Calma GDSII stream that reads back cleanly in an independent parser.
  • A NAND2 standard cell that exploits the nanosheet width freedom by swapping the N and P band widths to balance the series stack in the minimum 3-pitch footprint, with its GDSII, testbench and a FinFET comparison.
  • A 6T SRAM bitcell in the thin-cell topology whose cell and pull-up ratios are set by sheet width (36 / 24 / 20 nm) in a 0.0207 µm² high-density footprint, with GDSII, testbench, and static noise margin, write and read analysis against a 1-1-1 FinFET cell.
  • A ring-oscillator study: an 11-stage FO3 ring built from the cell as a Spectre testbench, as synthesisable RTL with preserved stages, and as a hierarchical GDSII, characterised over supply voltage against the FinFET baseline.
  • A scripted RTL-to-GDSII flow (Xcelium, Genus, Innovus) that synthesises and physically implements the inverter on the GAA library and streams out the routed block, together with the VMware Workstation configuration used to host the tools.

Section II describes the device and its model. Section III details the virtual environment, the cell-level flow and the RTL-to-GDSII flow. Section IV presents the results, Section V discusses limitations, and Section VI concludes. All scripts are listed in the Appendix.

II.GAA Nanosheet Device and Compact Model

A.Device structure

Fig. 1 shows the cross-section of the device used in this work, cut along the gate; Fig. 2 gives the transistor-level schematics of the four circuits built from it and Fig. 3 the same schematics as captured in the Virtuoso editor. Three silicon nanosheets of thickness TNS = 5 nm are stacked with a 9-nm vertical spacing that is filled by the work-function metal gate; the gate therefore wraps each sheet completely. The NMOS sheet width is WNS,N = 30 nm and the PMOS sheet width is WNS,P = 45 nm, which is the GAA equivalent of the FinFET's fin-count ratio and sets the inverter's β ratio. The gate length is Lg = 14 nm, with a 0.9-nm equivalent oxide thickness. The effective electrical width of a stack of N sheets is the total wrapped perimeter,

Weff = N · 2 (WNS + TNS)(1)

which gives 210 nm for the NMOS and 300 nm for the PMOS stack in a footprint of only 30 nm and 45 nm respectively. This width-per-footprint advantage over a fin (whose perimeter is 2Hfin + Wfin for a much taller structure) is one of the two reasons GAA is adopted; the other is the sub-70-mV/dec subthreshold swing that the wrapped gate maintains at 14 nm [1], [3].

B.BSIM-CMG representation in Spectre

Cadence Spectre supports the Berkeley BSIM-CMG common multi-gate model natively [5]. A nanosheet stack is represented with the double-gate geometry mode (geomod=0) in which tfin is the sheet thickness, hfin the sheet width and nfin the number of sheets, so the model's effective width is exactly (1). Substrate coupling is disabled (bulkmod=0) because the stack sits on an isolated bottom dielectric. The remaining parameters (gate work function phig, mobility u0, saturation velocity vsat, series resistance rdsw, short-channel terms dvt0/dvt1/eta0) were set to reproduce the IRDS 3-nm-class targets in Table I. The two model cards are listed in the Appendix (Listing 3).

C.Reference compact model

Because BSIM-CMG is only available inside the licensed simulator, a small reference model was written so the electrical figures can be reproduced anywhere and used as an acceptance check on the Spectre run. It uses a unified weak-to-strong-inversion charge expression in the EKV style with a velocity-saturation exponent α and a DIBL-like output-conductance term:

ID = K · Vovα · g(VDS),  Vov = α n φt ln[1 + exp((VGS − Vth)/α n φt)](2)
g(VDS) = (VDS/VDSAT) [1 + (VDS/VDSAT)²]−1/2 (1 + λ VDS)(3)

where n = SS/(φt ln 10) reproduces the specified subthreshold swing exactly in weak inversion and K is fixed by the on-current target at VGS = VDS = VDD. Table I lists the calibration and the resulting device figures.

III.Design Methodology

A.Virtualised EDA environment

All Cadence tools were run in a Linux guest under VMware Workstation on a Windows host, the configuration typical of an academic VLSI laboratory where licences are served over the campus network. The guest is a Red Hat-family distribution from the Cadence support matrix with 4 virtual cores, 16 GB RAM and a 120-GB thin-provisioned disk; NAT networking reaches the FlexNet licence server through CDS_LIC_FILE, and a VMware shared folder maps the project repository into the guest so that scripts edited on the host are visible to the tools without copying. A snapshot taken after installation makes a broken flow recoverable in seconds. The environment variables and paths used are given in the project README and reproduced in Listing 8.

Two virtualisation effects were relevant to the flow. Spectre's multithreading benefits from pinning the guest to physical cores rather than hyper-threads, and Innovus's memory-mapped design database needs the guest's swap to be at least as large as its RAM to avoid silent aborts during routing. Neither affects results, only run time.

B.Cell design in Virtuoso and Spectre

The inverter schematic (Fig. 2(a) and Fig. 3, Listing 3 subcircuit) instantiates one PMOS and one NMOS nanosheet stack between VDD and VSS. The testbench applies a piecewise-linear input with a 12-ps 10–90 % slew and drives a fan-out-of-4 load of 1.28 fF (four times the 0.32-fF input capacitance of the cell itself); a 0.35-fF lumped parasitic on the output stands in for drain, contact and gate-fringe capacitance before extraction. Three analyses are run: a DC sweep for the voltage-transfer characteristic (VTC), a transient for delay and energy, and a two-point DC for static leakage. Spectre's export measurements extract VM, tpHL, tpLH, energy per cycle and static power directly, so the same numbers are produced by ADE and by the batch run.

C.Layout and GDSII generation

The physical cell follows the 6-track template of a 3-nm-class library: height 6 × 28 nm = 168 nm, width two contacted gate pitches (2 × 48 nm = 96 nm), with half of a dummy diffusion-break gate on each vertical edge so that abutting cells share it. Table II lists the layer map. The GAA-specific features are the two nanosheet bands (layer 2) whose heights are the sheet widths of Table I, a stack-count marker (layer 2, datatype 1) that documents the three sheets for the technology file, and a gate-cut marker (layer 3, datatype 1) which is left open over the active gate because the inverter's N and P gates are common. Source/drain trench contacts (layer 4) land on the sheet bands, the gate contact (layer 5) sits in the 24-nm N/P separation region, via-0 (layer 6) connects to metal-1 (layer 7) which carries the two 24-nm power rails straddling the cell boundary, the source straps, the vertical output bar joining the two drains and the input landing pad. Pins are marked as datatype 1 and named with datatype 2 texts, which is the convention Innovus reads back from the merged cell GDS.

The layout was built in Virtuoso Layout XL and, in parallel, generated by the Python script of Listing 6, which contains a complete Calma GDSII stream writer (HEADER, BGNLIB, UNITS, BGNSTR, BOUNDARY, TEXT, SREF and the excess-64 real encoding) in about 100 lines and no third-party dependency. Having a second, independent producer of the same polygons served two purposes: it made the layer map an executable document, and it let the GDSII be regenerated and inspected in the host operating system where Virtuoso is not installed. Stream-out from Virtuoso uses strmout or the SKILL xstOut call of Listing 7 with the same layer map; stream-in of the script-generated file into Virtuoso produces an identical layout cellview, which was verified by XOR in the layout editor.

D.RTL-to-GDSII flow

Fig. 5 shows the digital implementation flow. The RTL (Listing 1) is a single continuous assignment; the value of running it through the flow is that every tool touches the GAA library. Genus reads the Liberty, LEF and RTL, elaborates, applies the constraints of Listing 2 (a 200-ps virtual clock, FO4 output load, 15-ps maximum transition) and maps onto the GAA3 library, where it selects INV_GAA_X1 (Listing 4). Innovus (Listing 5) imports the mapped netlist under a three-corner multi-mode multi-corner setup (typical, slow 0.63 V/125 °C, fast 0.77 V/−40 °C), floorplans a single 168-nm row at 60 % utilisation, routes the metal-1 follow-pin rails, places and optimises, routes with NanoRoute up to metal-4, adds filler cells, runs DRC and connectivity checks, extracts parasitics to SPEF, performs post-route timing and power analysis, and finally streams the routed block to GDSII with streamOut, merging the standard-cell GDS so the delivered file is complete down to the nanosheet layer.

IV.Results

Provenance. The figures and numbers in this section were produced by the reference compact model of Section II-C (spectre/ref_model.py), calibrated to the Table I targets. They are the acceptance values against which the Spectre/BSIM-CMG run of Listing 3 and the post-layout Innovus reports are compared in the VMware guest; the Spectre and Innovus report values should replace them in the final version of the manuscript.

A.Device characteristics

Fig. 6 shows the transfer characteristics of the two stacks. The subthreshold slopes are 68 mV/dec (NMOS) and 70 mV/dec (PMOS) by construction, the on-currents are 210 µA and 225 µA, and the resulting ION/IOFF ratios of 75 × 10³ and 105 × 10³ are consistent with published 3-nm GAA data at a standard threshold flavour [3]. The near-balance of N and P on-current at a 30/45-nm sheet-width ratio is the direct consequence of (1): the PMOS's 1.43 × wider sheets compensate its 0.75 × lower current density, which is exactly the design freedom fin quantisation removes.

B.Static transfer characteristic

Fig. 7 shows the VTC and its slope. The switching threshold VM = 350 mV sits at 50 % of VDD, confirming the β-ratio choice. The maximum small-signal gain of 28 is high for a 14-nm device and reflects the low output conductance of the wrapped gate; it produces a steep transition with unity-gain points at VIL = 295 mV and VIH = 395 mV. Output levels are VOH = 661 mV and VOL = 40 mV, so the noise margins are NML = 255 mV and NMH = 266 mV, each above 36 % of the supply.

C.Transient response, delay and energy

Fig. 8 shows the response to the 12-ps-slew input step for the intrinsic (FO1) and FO4 loads. Table III summarises the timing and energy figures. The FO4 propagation delay of 5.77 ps and the near-equal tpHL/tpLH again confirm the drive balance. The energy of 0.84 fJ per full cycle at FO4 corresponds to 0.84 µW at 1 GHz with 100 % activity, while the static power is 1.74 nW, a dynamic-to-static ratio of about 484 at 1 GHz.

E.Comparison with a FinFET inverter

To quantify what the change of device brings, the same reference model, testbench and cell template were re-run with a 5-nm-class FinFET calibration: an 18-nm gate, 50-nm-tall and 6-nm-wide fins at a 27-nm fin pitch, two fins per device in a 6-track 180-nm cell at a 54-nm contacted gate pitch, with subthreshold swings of 72/74 mV/dec and the higher drain-induced barrier lowering of a tri-gate channel [2], [4], [6]. Table V sets the two side by side. Because a fin adds drive only in whole-fin steps, the FinFET PMOS is limited to the same two fins as the NMOS and so delivers only 148 µA against 191 µA, which shows up as a 1.24-ps rise/fall skew and a 335-mV switching threshold; the GAA cell tunes the P sheet to 45 nm and balances the edges to within 0.01 ps. The three wrapped 30-nm sheets fit a 210-nm effective width into a 30-nm footprint, where two fins need 54 nm of pitch for 212 nm. The result is a 16 % lower FO4 delay and a 17 % smaller cell for essentially the same energy per cycle, since the switched capacitance is set by the load and the parasitics rather than by the channel.

F.Ring oscillator

A ring oscillator (RO) is the standard vehicle for reporting a technology's switching speed because it removes the arbitrary stimulus slew of a single-inverter measurement: each stage is driven by the natural edge of the previous one. An 11-stage RO was built from INV_GAA_X1 in the fan-out-of-3 configuration used for library characterisation, in which every node drives the next stage plus two dummy inverters. The Spectre testbench (Listing 11) kick-starts the loop with an initial condition and sweeps VDD from 0.5 to 0.8 V; the RTL of Listing 12 keeps the eleven stages through synthesis with preserve attributes so Genus and Innovus can implement the same ring, and Listing 13 generates the hierarchical RO GDSII of Fig. 10 from eleven abutted inverter cells wired on metal-2. The reference model reproduces the RO by integrating the eleven node voltages with each node loaded by 3 Cin + Cpar = 1.31 fF.

Fig. 9 shows the steady-state waveforms and the supply dependence. At 0.7 V the GAA ring oscillates at 25.3 GHz, a stage delay of 1.80 ps, drawing 181 µW, i.e. 652 aJ per stage per cycle; the FinFET ring built the same way runs at 20.3 GHz (2.24 ps per stage). The stage delay is well below the step-driven FO4 delay of Table III because the ring's own edges are much faster than the 12-ps stimulus used there. Frequency scales almost linearly with supply over the sweep, the signature of a velocity-saturated device, and the GAA advantage of 25 % at nominal supply widens to 32 % at 0.5 V where its lower threshold and steeper swing matter most. The energy per stage follows C VDD², so the energy-delay product favours the GAA ring by 19 % at 0.7 V.

G.Two-input NAND gate

The NAND2 is the first cell in which the GAA width freedom changes a design decision rather than a number. Its pull-down is two NMOS in series and its pull-up two PMOS in parallel, so with the inverter's 30-nm N / 45-nm P bands the worst-case pull-down (one series stack) would be roughly half the pull-up (one PMOS). In a FinFET library this is corrected by adding a fin to each NMOS, which adds a whole fin pitch to the cell; a nanosheet cell simply swaps the two band widths. NAND2_GAA_X1 (Fig. 11) therefore uses 45-nm sheets for the series NMOS and 30-nm sheets for the parallel PMOS, in the same 6-track template and the minimum three gate pitches (144 nm). The internal stack node X is a contact-only diffusion, the output is collected on metal-2 through via-1 from the shared PMOS drain and the outer NMOS drain, and the two gate contacts sit in a 35-nm N/P gap on the input track. Listing 15 is the Spectre testbench with width-swapped BSIM-CMG cards, Listing 16 the RTL that Genus maps onto the cell, and Listing 17 the GDSII generator.

Fig. 12 shows the three transfer curves and the two timing arcs. With the swapped bands the series stack delivers 165 µA against 157 µA for a single PMOS, a ratio of 1.05, so the tied-input switching threshold of 375 mV is near mid-supply and the two single-input arcs are within 0.15 ps of each other. The FinFET cell, held at two fins per device, has a pull-down/pull-up ratio of 0.69 and a 8.66-ps worst-case delay against 7.60 ps, while occupying 21 % more area. The B-input high-to-low arc is the slower of the two falling arcs in both technologies: its transistor is the outer device of the stack, so its transition must also discharge the internal node before the output starts to fall. The leakage rows show the stack effect: with both inputs low the two off NMOS in series leak 2.9 × less than a single off device because the internal node settles a few tens of millivolts above ground, which gives the top device a negative gate-source voltage and the bottom device a smaller drain bias, an effect the reference model captures through the internal-node DC solution and BSIM-CMG through its full subthreshold formulation.

H.Six-transistor SRAM bitcell

SRAM is where the nanosheet's continuous width matters most, because a bitcell's stability and writability are set by two ratios that a FinFET high-density cell cannot tune: the cell ratio β = IPD/IPG that limits the read disturb, and the pull-up ratio γ = IPG/IPU that sets the write trip point. A 1-fin-per-device FinFET cell has β = 1 by construction and can only reach β = 2 by adding a whole fin to the pull-down, which is the high-performance cell with roughly a third more area. The GAA bitcell of Fig. 13, SRAM6T_GAA_HD, keeps the thin-cell topology [12] at two gate pitches of height (96 nm) and 216 nm of width (0.0207 µm², in line with the 0.020–0.021 µm² high-density cells reported at 3 nm [3], [4]) and sets the ratios by sheet width alone: the NMOS stripe is jogged so the pull-down uses 36-nm sheets and the access transistor 24-nm sheets, and the pull-up uses 20-nm sheets, chosen so that the write trip point matches the FinFET cell. The two inverters are cross-coupled through butted contacts that join the end of each gate row to the opposite storage node's PMOS drain; bit lines, supply and ground run vertically on metal-2 and the word line horizontally on metal-3. Listing 19 is the Spectre testbench (butterfly curves with the loop broken by a controlled source, write sweep, read current, leakage and a supply sweep) and Listing 20 the GDSII generator; Listing 21 is the reference analysis, which solves each storage node by bisection and extracts the static noise margin as the largest square that fits between a transfer curve and its mirror.

Table VIII and Fig. 14 give the results. The hold static noise margin, set by the two inverter transfer curves alone, is within 5 % of the FinFET cell's, since the GAA pull-up is deliberately its weakest device; the read margin is where the sizing pays: the GAA cell's β = 1.41 holds the '0' node to 135 mV during a read against 169 mV for the β = 1 FinFET cell, which lifts the read SNM from 94 mV to 105 mV. On the write side the pull-up width sets γ = 1.55, which puts the write trip voltage at 293 mV against 294 mV for the FinFET cell: the read-margin gain is obtained at unchanged writability, and a wider pull-up would trade it back for hold margin. The read current, which sets the bit-line discharge time and therefore the access time, is 112.1 µA against 51.4 µA. Fig. 14 (right) shows that the read margin scales with supply almost as steadily as the hold margin down to 0.4 V, which is the property that lets GAA SRAM lower its minimum operating voltage. The cost of the wider pull-down is visible in the leakage row; a production cell would use a high-threshold flavour of the same devices, which the SVT calibration of Table I does not represent.

V.Discussion

Position against the roadmap. The geometry of Table I matches the IRDS 2023 "3-nm" logic node (14–16-nm gate length, 45–48-nm contacted gate pitch, 24–28-nm minimum metal pitch, 0.7-V supply) [4], and the FO4 delay and energy of Table III are in the range reported for early GAA nanosheet ring oscillators and inverters [1], [3]. The 6-track cell height of 168 nm is at the roadmap value; the 96-nm width is the minimum for a single-gate cell with shared diffusion breaks.

What GAA changes in the cell. Table V makes the trade explicit for the inverter, Table VII for the NAND2, where the sheet-width swap replaces a fin-count change, and Table VIII for the SRAM bitcell, where three different sheet widths set the cell and pull-up ratios that a one-fin cell cannot adjust. Compared with a FinFET inverter at the same pitch, the layout has no fin grid: drive is set by the height of the nanosheet band, which the layout engineer can choose per device within the design-rule window, and the N/P sheet-width ratio replaces the fin-count ratio. The stack-count marker and the gate-cut layer are new; the rest of the metallisation is unchanged, which is why the RTL-to-GDSII flow needed no modification beyond pointing at the GAA library.

Limitations. The rule set is generic; a foundry 3-nm GAA PDK has different layer numbering, an additional buried power rail or backside power option, and considerably tighter and more numerous rules, so the layout here should be treated as a topology, not as tape-out ready. The results section reports reference-model values that must be replaced by the Spectre/BSIM-CMG and post-layout Innovus figures once the flow is executed in the licensed environment; the model was calibrated to the same targets so the two are expected to agree within the calibration tolerance, but extraction will add parasitic capacitance that the 0.35-fF lumped estimate only approximates. The ring-oscillator frequencies are optimistic for the same reason, since the model carries no Miller or gate-overlap capacitance and no interconnect load; the BSIM-CMG cards include cgso/cgdo and the Innovus SPEF adds the wiring, so the Spectre and post-layout RO frequencies will be lower. Variability (sheet-thickness and work-function variation) and self-heating in the stacked, dielectrically isolated channel were not analysed and are natural next steps.

Reproducibility. Every script referenced in this paper is listed in the Appendix and released in the project repository under vlsi/gaa_inverter/. The GDSII files, the SVG renderings of their polygons, the schematics of Fig. 2 and Fig. 3 and the reference-model results are regenerated by Python commands with no dependencies beyond the standard library; PNG renderings of every schematic and layout are kept under docs/figures/.

VI.Conclusion

A gate-all-around nanosheet CMOS inverter was designed, laid out and carried through a complete Cadence RTL-to-GDSII flow inside a VMware Workstation guest. The device was represented with BSIM-CMG in Spectre, the cell was drawn to a documented 3-nm-class layer map and delivered as a verified GDSII stream, and Genus and Innovus synthesised and physically implemented the cell to a second, block-level GDSII. At 0.7 V the inverter shows a 350-mV switching threshold, a gain of 28, noise margins above 250 mV, a 5.77-ps FO4 delay and 0.84 fJ per cycle in 0.0161 µm², and an 11-stage FO3 ring oscillator built from it runs at 25.3 GHz, 25 % faster than the FinFET ring. The NAND2 cell shows the design consequence of continuous width tuning: swapping the sheet widths of the two bands balances the series stack without the extra fin pitch a FinFET cell needs, and the 6T bitcell turns the same freedom into a 12 % higher read margin at the same write trip point and equal area. Because every artefact, from the model card to the stream writer, is scripted and released, the work serves as a template for research groups moving to GAA technology on virtualised EDA infrastructure, and as the cell-level foundation for larger GAA standard-cell libraries and memory arrays.

"""
gen_gaa_inverter_gds.py
-----------------------

# 1. Minimal GDSII stream writer (Calma GDSII Stream Format, release 6)
# ----------------------------------------------------------------------------
HEADER, BGNLIB, LIBNAME, UNITS, ENDLIB, BGNSTR, STRNAME, ENDSTR = (
    0x00, 0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07)
BOUNDARY, PATH, SREF, TEXT, LAYER, DATATYPE, XY, ENDEL = (
    0x08, 0x09, 0x0A, 0x0C, 0x0D, 0x0E, 0x10, 0x11)
SNAME, TEXTTYPE, PRESENTATION, STRING, MAG = 0x12, 0x16, 0x17, 0x19, 0x1B
WIDTH = 0x0F

DT_NONE, DT_BITARRAY, DT_INT2, DT_INT4, DT_REAL8, DT_ASCII = 0, 1, 2, 3, 5, 6


def _real8(value: float) -> bytes:
    """Encode a float as GDSII 8-byte excess-64 base-16 real."""
    if value == 0.0:
        return b"\x00" * 8
    sign = 0
    if value < 0:
        sign = 0x80
        value = -value
    exponent = 0
    while value >= 1.0:
        value /= 16.0
        exponent += 1
    while value < 1.0 / 16.0:
        value *= 16.0
        exponent -= 1
    mantissa = int(round(value * (1 << 56)))
    if mantissa >= (1 << 56):          # rounding overflow guard
        mantissa >>= 4
        exponent += 1
    return bytes([sign | (exponent + 64)]) + mantissa.to_bytes(7, "big")


def _record(rtype: int, dtype: int, payload: bytes = b"") -> bytes:
    length = 4 + len(payload)
    return struct.pack(">HBB", length, rtype, dtype) + payload


def _ascii(rtype: int, text: str) -> bytes:
    data = text.encode("ascii")
    if len(data) % 2:
        data += b"\x00"
    return _record(rtype, DT_ASCII, data)


def _int2(rtype: int, *values: int) -> bytes:
    return _record(rtype, DT_INT2, struct.pack(">%dh" % len(values), *values))


def _timestamp() -> bytes:
    t = time.localtime()
    stamp = (t.tm_year, t.tm_mon, t.tm_mday, t.tm_hour, t.tm_min, t.tm_sec)
    return struct.pack(">12h", *(stamp + stamp))


class GdsLibrary:
    def __init__(self, name: str, user_unit=1e-6, db_unit=1e-9):
        self.name = name
        self.user_unit = user_unit
        self.db_unit = db_unit
        self.cells = []

    def write(self, path: str) -> None:
        out = bytearray()
        out += _int2(HEADER, 600)
        out += _record(BGNLIB, DT_INT2, _timestamp())
        out += _ascii(LIBNAME, self.name)
        out += _record(UNITS, DT_REAL8,
                       _real8(self.db_unit / self.user_unit) + _real8(self.db_unit))
        for cell in self.cells:
            out += cell.to_bytes()
        out += _record(ENDLIB, DT_NONE)
        with open(path, "wb") as fh:
            fh.write(out)


class GdsCell:
    def __init__(self, name: str):
        self.name = name
        self.polygons = []   # (layer, datatype, [(x, y), ...], tag)
        self.labels = []     # (layer, texttype, (x, y), string)
        self.refs = []       # (cellname, (x, y))

    def rect(self, layer, datatype, x0, y0, x1, y1, tag=""):
        pts = [(x0, y0), (x1, y0), (x1, y1), (x0, y1)]
        self.polygons.append((layer, datatype, pts, tag))

    def label(self, layer, texttype, x, y, text):
        self.labels.append((layer, texttype, (x, y), text))

    def ref(self, cellname, x, y):
        self.refs.append((cellname, (x, y)))

    def to_bytes(self) -> bytes:
        out = bytearray()
        out += _record(BGNSTR, DT_INT2, _timestamp())
        out += _ascii(STRNAME, self.name)
        for layer, datatype, pts, _tag in self.polygons:
            out += _record(BOUNDARY, DT_NONE)
            out += _int2(LAYER, layer)
            out += _int2(DATATYPE, datatype)
            closed = list(pts) + [pts[0]]
            flat = [int(round(c)) for p in closed for c in p]
            out += _record(XY, DT_INT4, struct.pack(">%di" % len(flat), *flat))
            out += _record(ENDEL, DT_NONE)
        for layer, texttype, (x, y), text in self.labels:
            out += _record(TEXT, DT_NONE)
            out += _int2(LAYER, layer)
            out += _int2(TEXTTYPE, texttype)
            out += _record(PRESENTATION, DT_BITARRAY, struct.pack(">H", 0x0005))  # centre/centre
            out += _record(MAG, DT_REAL8, _real8(0.02))
            out += _record(XY, DT_INT4, struct.pack(">2i", int(x), int(y)))
            out += _ascii(STRING, text)
            out += _record(ENDEL, DT_NONE)
        for cellname, (x, y) in self.refs:
            out += _record(SREF, DT_NONE)
            out += _ascii(SNAME, cellname)
            out += _record(XY, DT_INT4, struct.pack(">2i", int(x), int(y)))
            out += _record(ENDEL, DT_NONE)
        out += _record(ENDSTR, DT_NONE)
        return bytes(out)

def build_inverter() -> GdsCell:
    t = TECH
    c = GdsCell("INV_GAA_X1")
    xc = CELL_W // 2                      # gate centre
    lg2 = t["LG"] // 2

    # -- boundary and wells ----------------------------------------------------
    c.rect(*L["PRBOUND"], 0, 0, CELL_W, CELL_H, "prBoundary")
    c.rect(*L["NWELL"], 0, CELL_H // 2, CELL_W, CELL_H, "NWELL")

    # -- nanosheet stacks (active) ---------------------------------------------
    n_y0, n_y1 = 34, 34 + t["NS_W_N"]                      # NMOS sheet band (34..64)
    p_y1 = CELL_H - 34
    p_y0 = p_y1 - t["NS_W_P"]                              # PMOS sheet band (89..134)
    act_x0, act_x1 = 8, CELL_W - 8
    c.rect(*L["NSHEET"], act_x0, n_y0, act_x1, n_y1, "NS_N")
    c.rect(*L["NSHEET"], act_x0, p_y0, act_x1, p_y1, "NS_P")
    # stack-count marker (3 sheets) drawn as thin stripes for visualisation
    for i in range(t["NS_N"]):
        dy_n = n_y0 + 4 + i * ((t["NS_W_N"] - 8) // t["NS_N"])
        dy_p = p_y0 + 5 + i * ((t["NS_W_P"] - 10) // t["NS_N"])
        c.rect(*L["NS_STACK_MARK"], act_x0 + 2, dy_n, act_x1 - 2, dy_n + 2, "sheet")
        c.rect(*L["NS_STACK_MARK"], act_x0 + 2, dy_p, act_x1 - 2, dy_p + 2, "sheet")

    c.rect(*L["GATE"], xc - lg2, 14, xc + lg2, CELL_H - 14, "gate")

#!/usr/bin/env python3
"""
ref_model.py -- dependency-free reference simulation of the GAA nanosheet inverter.

A unified EKV-style compact model (weak->strong inversion continuous, velocity-
saturation exponent alpha, DIBL-like output conductance) is calibrated to
IRDS-2023 3-nm-class nanosheet targets. It reproduces the metrics that the
Spectre/BSIM-CMG testbench `gaa_inv_tb.scs` extracts, so results can be checked
before/after running Cadence in the VMware guest.  Writes results.json and SVG plots.
"""
import json, math, os

PHI_T = 0.02585                 # kT/q at 300 K
VDD = 0.70
TECH = dict(NS_N=3, NS_T=5e-9, NS_W_N=30e-9, NS_W_P=45e-9, LG=14e-9, EOT=0.9e-9)

def w_eff(w):                    # gate-all-around perimeter * sheet count
    return TECH["NS_N"] * 2 * (w + TECH["NS_T"])

DEV = {
    "n": dict(vth=0.24, ss=0.068, alpha=1.25, lam=0.12, jon=1.00e-3, weff=w_eff(TECH["NS_W_N"]), sgn=+1),
    "p": dict(vth=0.26, ss=0.070, alpha=1.25, lam=0.14, jon=0.75e-3, weff=w_eff(TECH["NS_W_P"]), sgn=-1),
}
FINFET = os.environ.get("GAA_TECH", "gaa") == "finfet"
if FINFET:
    # 5-nm-class FinFET reference: Lg 18 nm, fin H 50 nm / W 6 nm, 2 fins per device (drive
    # is quantised: the N/P ratio cannot be tuned continuously), SS ~72/74 mV/dec, higher DIBL.
    TECH = dict(FIN_N=2, FIN_H=50e-9, FIN_W=6e-9, LG=18e-9, EOT=0.9e-9)
    def w_eff_fin(): return TECH["FIN_N"] * (2 * TECH["FIN_H"] + TECH["FIN_W"])
    DEV = {
        "n": dict(vth=0.26, ss=0.072, alpha=1.25, lam=0.18, jon=0.90e-3, weff=w_eff_fin(), sgn=+1),
        "p": dict(vth=0.28, ss=0.074, alpha=1.25, lam=0.20, jon=0.70e-3, weff=w_eff_fin(), sgn=-1),
    }
for d in DEV.values():
    d["n_ss"] = d["ss"] / (PHI_T * math.log(10.0))
    d["ion"] = d["jon"] * d["weff"] * 1e6        # A  (jon in A/um, weff in m)

def _vov(d, vgs):
    s = d["alpha"] * d["n_ss"] * PHI_T
    x = (vgs - d["vth"]) / s
    return s * (math.log1p(math.exp(x)) if x < 40 else x)

def _g(d, vov, vds):
    vdsat = math.sqrt((0.55 * vov) ** 2 + (3 * PHI_T) ** 2)
    r = vds / vdsat
    return r / (1.0 + r ** 2) ** 0.5 * (1.0 + d["lam"] * vds)

def ids(dev, vgs, vds):
    """Drain current magnitude (A). vgs, vds given as |values| for PMOS."""
    d = DEV[dev]
    if "k" not in d:
        d["k"] = 1.0
        d["k"] = d["ion"] / ids(dev, VDD, VDD)
    vov = _vov(d, vgs)
    return d["k"] * vov ** d["alpha"] * _g(d, vov, vds)

def i_n(vin, vout): return ids("n", vin, vout)
def i_p(vin, vout): return ids("p", VDD - vin, VDD - vout)

def vtc(npts=141):
    pts = []
    for i in range(npts):
        vin = VDD * i / (npts - 1)
        lo, hi = 0.0, VDD
        for _ in range(60):                       # bisection on I_n(vout) = I_p(vout)
            mid = 0.5 * (lo + hi)
            if i_n(vin, mid) > i_p(vin, mid): hi = mid
            else: lo = mid
        pts.append((vin, 0.5 * (lo + hi)))
    return pts

def metrics_static(curve):
    vin = [p[0] for p in curve]; vout = [p[1] for p in curve]
    gain = [0.0] * len(curve)
    for i in range(1, len(curve) - 1):
        gain[i] = (vout[i + 1] - vout[i - 1]) / (vin[i + 1] - vin[i - 1])
    imax = min(range(len(gain)), key=lambda i: gain[i])
    # switching threshold: vout = vin
    vm = next(vin[i] for i in range(len(curve)) if vout[i] <= vin[i])
    # unity-gain points -> VIL, VIH, VOL, VOH
    il = max(i for i in range(imax) if gain[i] > -1.0)
    ih = min(i for i in range(imax, len(curve)) if gain[i] > -1.0)
    VIL, VIH, VOH, VOL = vin[il], vin[ih], vout[il], vout[ih]
    return dict(VM=vm, gain_max=gain[imax], VIL=VIL, VIH=VIH, VOH=VOH, VOL=VOL,
                NMH=VOH - VIH, NML=VIL - VOL, gain=gain)

def transient(cl, tr=12e-12, tstop=80e-12, dt=2e-15, cpar=0.35e-15):
    """Input: 0->VDD ramp at t0 then VDD->0 at t1 (10-90 % slew = tr). Euler on C dV/dt."""
    C = cl + cpar
    t0, t1 = 10e-12, 45e-12
    ramp = tr / 0.8
    def vin_t(t):
        if t < t0: return 0.0
        if t < t0 + ramp: return VDD * (t - t0) / ramp
        if t < t1: return VDD
        if t < t1 + ramp: return VDD * (1 - (t - t1) / ramp)
        return 0.0
    t, vout = 0.0, VDD
    ts, vins, vouts, idds = [], [], [], []
    e_supply = 0.0
    while t <= tstop:
        vi = vin_t(t)
        ip, in_ = i_p(vi, vout), i_n(vi, vout)
        vout += dt * (ip - in_) / C
        vout = min(max(vout, -0.05), VDD + 0.05)
        e_supply += ip * VDD * dt
        if int(t / dt) % 25 == 0:
            ts.append(t); vins.append(vi); vouts.append(vout); idds.append(ip)
        t += dt
    def cross(sig, level, rising, tstart):
        for i in range(1, len(ts)):
            if ts[i] < tstart: continue
            a, b = sig[i - 1], sig[i]
            if (rising and a < level <= b) or (not rising and a > level >= b):
                return ts[i - 1] + (level - a) / (b - a) * (ts[i] - ts[i - 1])
        return float("nan")
    half = VDD / 2
    tphl = cross(vouts, half, False, t0) - cross(vins, half, True, t0)
    tplh = cross(vouts, half, True, t1) - cross(vins, half, False, t1)
    tf = cross(vouts, 0.1 * VDD, False, t0) - cross(vouts, 0.9 * VDD, False, t0)
    trr = cross(vouts, 0.9 * VDD, True, t1) - cross(vouts, 0.1 * VDD, True, t1)
    e_leak = 0.5 * (i_n(0, VDD) + i_p(VDD, 0)) * VDD * tstop
    return dict(tpHL=tphl, tpLH=tplh, tpd=0.5 * (tphl + tplh), tfall=tf, trise=trr,
                E_cycle=e_supply - e_leak, wave=dict(t=ts, vin=vins, vout=vouts, idd=idds))

def idvg(dev):
    rows = []
    for i in range(0, 71):
        vgs = VDD * i / 70
        rows.append((vgs, ids(dev, vgs, VDD), ids(dev, vgs, 0.05)))
    return rows

# ------------------------------------------------------------------ SVG helpers
def svg_chart(w, h, series, xlab, ylab, xlim, ylim, log=False, extra=""):
    ml, mr, mt, mb = 52, 16, 12, 40
    pw, ph = w - ml - mr, h - mt - mb
    def X(x): return ml + (x - xlim[0]) / (xlim[1] - xlim[0]) * pw
    def Y(y):
        if log: y = math.log10(max(y, 1e-30)); a, b = math.log10(ylim[0]), math.log10(ylim[1])

"""
ro.py -- N-stage ring-oscillator simulation with the reference compact model.

    python3 ro.py                 # GAA nanosheet RO11: results_ro.json
    GAA_TECH=finfet python3 ro.py # FinFET baseline:    results_ro_finfet.json
    python3 ro.py --figs          # fig_ro_wave.svg, fig_ro_fvdd.svg, fig_ro_pvdd.svg from both JSONs

Each node is loaded by the next stage's gate capacitance (C_in) and its own drain
parasitics (C_par); node voltages are integrated with forward Euler (dt = 8 fs).
"""
import json, math, os, sys
import ref_model as rm

N_STAGES = 11
CIN  = 0.30e-15 if rm.FINFET else 0.32e-15
CPAR = 0.40e-15 if rm.FINFET else 0.35e-15
FANOUT = 3                      # FO3-loaded RO: library-characterisation convention
C_NODE = FANOUT * CIN + CPAR

def simulate(vdd, n=N_STAGES, tstop=600e-12, dt=8e-15):
    rm.VDD = vdd                                   # model closes over module VDD
    v = [vdd if i % 2 else 0.0 for i in range(n)]
    v[0] = vdd * 0.45                              # kick
    t = 0.0; ts, v0, v1, idd = [], [], [], []
    step = 0
    while t <= tstop:
        ip_sum = 0.0; nv = v[:]
        for i in range(n):
            vin = v[i - 1]
            ip = rm.i_p(vin, v[i]); inn = rm.i_n(vin, v[i])
            ip_sum += ip
            nv[i] = min(max(v[i] + dt * (ip - inn) / C_NODE, -0.05), vdd + 0.05)
        v = nv
        if step % 10 == 0:
            ts.append(t); v0.append(v[0]); v1.append(v[1]); idd.append(ip_sum)
        t += dt; step += 1
    # period from rising half-VDD crossings of node 0 in the second half of the run
    half = vdd / 2; cr = []
    for k in range(1, len(ts)):
        if ts[k] > tstop / 2 and v0[k - 1] < half <= v0[k]:
            cr.append(ts[k - 1] + (half - v0[k - 1]) / (v0[k] - v0[k - 1]) * (ts[k] - ts[k - 1]))
    if len(cr) < 3:
        return None
    T = (cr[-1] - cr[0]) / (len(cr) - 1)
    sel = [k for k in range(len(ts)) if cr[0] <= ts[k] <= cr[-1]]
    p_avg = sum(idd[k] for k in sel) / len(sel) * vdd
    p_leak = 0.5 * (rm.i_n(0.0, vdd) + rm.i_p(vdd, 0.0)) * vdd * n
    return dict(VDD=vdd, N=n, f_Hz=1.0 / T, T_s=T, t_stage_s=T / (2 * n), P_W=p_avg, P_leak_W=p_leak,
                E_stage_J=(p_avg - p_leak) * T / n,        # dynamic energy per stage per cycle
                wave=dict(t=[round(x * 1e12, 3) for x in ts], v0=[round(x, 4) for x in v0],
                          v1=[round(x, 4) for x in v1]))

else:
    WN = rm.w_eff(45e-9) / rm.w_eff(30e-9)  # 300/210

CPAR = 0.45e-15 if rm.FINFET else 0.40e-15  # two drains on the output node
CX   = 0.15e-15                             # internal stack node

def i_n(vg, vs, vd): return WN * rm.ids("n", vg - vs, vd - vs) if vd > vs else -WN * rm.ids("n", vg - vd, vs - vd)
def i_p(vg, vd): return WP * rm.i_p(vg, vd)

def stack_x(va, vb, vy):
    """Internal node X for which I(MNA) = I(MNB) at DC; bisection."""
    lo, hi = 0.0, max(vy, 0.0)
    for _ in range(60):
        mid = 0.5 * (lo + hi)
        if i_n(va, 0.0, mid) > i_n(vb, mid, vy): hi = mid   # bottom device discharges X faster than top charges it
        else: lo = mid
    return 0.5 * (lo + hi)

def i_pd(va, vb, vy):
    return i_n(va, 0.0, stack_x(va, vb, vy))

def vout_dc(va, vb):
    lo, hi = 0.0, rm.VDD
    for _ in range(60):
        mid = 0.5 * (lo + hi)
        if i_pd(va, vb, mid) > i_p(va, mid) + i_p(vb, mid): hi = mid
        else: lo = mid
    return 0.5 * (lo + hi)

        pts.append((v, vout_dc(va, vb)))
    return pts

def transient(mode, cl, tr=12e-12, tstop=80e-12, dt=2e-15):
    """Input 'mode' ('A', 'B' or 'AB') gets 0->VDD->0; the other input is held at VDD."""
    C = cl + CPAR; V = rm.VDD; t0, t1 = 10e-12, 45e-12; ramp = tr / 0.8
    def stim(t):
        if t < t0: return 0.0
        if t < t0 + ramp: return V * (t - t0) / ramp
        if t < t1: return V
        if t < t1 + ramp: return V * (1 - (t - t1) / ramp)
        return 0.0
    vy, vx = V, V - 0.05
    t = 0.0; ts, vin, vout, e = [], [], [], 0.0
    k = 0
    while t <= tstop:
        s = stim(t)
        va = s if mode in ("A", "AB") else V
        vb = s if mode in ("B", "AB") else V
        ip = i_p(va, vy) + i_p(vb, vy)
        ia = i_n(va, 0.0, vx); ib = i_n(vb, vx, vy)
        vy += dt * (ip - ib) / C
        vx += dt * (ib - ia) / CX          # MNB charges X from Y, MNA discharges it to VSS
        vy = min(max(vy, -0.05), V + 0.05); vx = min(max(vx, -0.05), V + 0.05)
        e += ip * V * dt
        if k % 25 == 0: ts.append(t); vin.append(s); vout.append(vy)
        t += dt; k += 1
    def cross(sig, level, rising, tstart):
        for i in range(1, len(ts)):
            if ts[i] < tstart: continue
            a, b = sig[i - 1], sig[i]
            if (rising and a < level <= b) or (not rising and a > level >= b):
                return ts[i - 1] + (level - a) / (b - a) * (ts[i] - ts[i - 1])
        return float("nan")

    tphl = cross(vout, h, False, t0) - cross(vin, h, True, t0)
    tplh = cross(vout, h, True, t1) - cross(vin, h, False, t1)
    return dict(tpHL=tphl, tpLH=tplh, tpd=0.5 * (tphl + tplh), E_cycle=e, wave=dict(t=ts, vin=vin, vout=vout))

def i_n(w, vg, vs, vd):
    if vd >= vs: return w * rm.ids("n", vg - vs, vd - vs)
    return -w * rm.ids("n", vg - vd, vs - vd)
def i_pu(vg, vd):   return W_PU * rm.i_p(vg, vd)          # PMOS source at VDD

def node(v_other, bl, wl, vdd):
    """DC voltage of a storage node driven by the other node (gate) with its access transistor
    to bit line 'bl' under word line 'wl'. Bisection on the node voltage."""
    lo, hi = 0.0, vdd
    for _ in range(60):
        mid = 0.5 * (lo + hi)
        # access transistor current into the node (positive when BL > node)
        i_pg = i_n(W_PG, wl, mid, bl) if bl >= mid else -i_n(W_PG, wl, bl, mid)
        i_in = i_pu(v_other, mid) + i_pg
        i_out = i_n(W_PD, v_other, 0.0, mid)
        if i_in > i_out: lo = mid
        else: hi = mid
    return 0.5 * (lo + hi)

def butterfly(mode, vdd, npts=121):
    wl = vdd if mode == "read" else 0.0
    xs = [vdd * i / (npts - 1) for i in range(npts)]
    return [(x, node(x, vdd, wl, vdd)) for x in xs]

def snm(curve, vdd):
    """Side of the largest square that fits in one lobe between y = f(x) and its mirror x = f(y).
    For a square [x0, x0+s] x [y0, y0+s] under curve 1 and right of curve 2 the binding corners are
    top-right (y0 + s <= f(x0 + s)) and bottom-left (x0 >= f(y0)); with y0 = f(x0+s) - s the
    condition is x0 >= f(f(x0+s) - s).  Both inverters are identical, so one lobe suffices."""
    xs = [p[0] for p in curve]; ys = [p[1] for p in curve]
    def f(x):
        if x <= xs[0]: return ys[0]
        if x >= xs[-1]: return ys[-1]
        k = int((len(xs) - 1) * (x - xs[0]) / (xs[-1] - xs[0]))
        k = min(max(k, 0), len(xs) - 2)
        return ys[k] + (ys[k + 1] - ys[k]) * (x - xs[k]) / (xs[k + 1] - xs[k])
    best = 0.0
    for i in range(0, len(xs) - 1):
        x0 = xs[i]
        lo, hi = 0.0, vdd - x0
        for _ in range(40):
            mid = 0.5 * (lo + hi)
            y0 = f(x0 + mid) - mid
            if y0 >= 0 and x0 >= f(y0): lo = mid
            else: hi = mid
        best = max(best, lo)
    return best

def dc_state(bl, blb, wl, vdd, q=None, qb=None, iters=400):
    q = vdd if q is None else q; qb = 0.0 if qb is None else qb
    for _ in range(iters):
        q_new = node(qb, bl, wl, vdd)
        qb_new = node(q_new, blb, wl, vdd)
        if abs(q_new - q) < 1e-6 and abs(qb_new - qb) < 1e-6:
            q, qb = q_new, qb_new; break
        q, qb = 0.5 * (q + q_new), 0.5 * (qb + qb_new)
    return q, qb

def write_trip(vdd):
    """Cell holds Q=1: sweep BL down (BLB=VDD, WL=VDD) until the cell flips (Q < QB)."""
    lo, hi = 0.0, vdd

        if q < qb: lo = mid

    return 0.5 * (lo + hi)

         + i_n(W_PG, 0.0, 0.0, vdd))          # PG2 off, BLB=VDD, QB=0
    return i

def png_read(path):
    d = open(path, "rb").read(); pos = 8; idat = b""; w = h = bpp = 0
    while pos < len(d):
        n, t = struct.unpack(">I4s", d[pos:pos + 8]); body = d[pos + 8:pos + 8 + n]; pos += 12 + n
        if t == b"IHDR": w, h, _bd, ct = struct.unpack(">IIBB", body[:10]); bpp = {2: 3, 6: 4}[ct]
        elif t == b"IDAT": idat += body
    raw = zlib.decompress(idat); stride = w * bpp; rows = []; prev = bytearray(stride); p = 0
    for _ in range(h):
        f = raw[p]; line = bytearray(raw[p + 1:p + 1 + stride]); p += 1 + stride
        for i in range(stride):
            a = line[i - bpp] if i >= bpp else 0; b = prev[i]; c = prev[i - bpp] if i >= bpp else 0
            if f == 1: line[i] = (line[i] + a) & 255
            elif f == 2: line[i] = (line[i] + b) & 255
            elif f == 3: line[i] = (line[i] + (a + b) // 2) & 255
            elif f == 4:
                pp = a + b - c; pa, pb, pc = abs(pp - a), abs(pp - b), abs(pp - c)
                line[i] = (line[i] + (a if pa <= pb and pa <= pc else b if pb <= pc else c)) & 255
        rows.append(bytes(line)); prev = line
    return w, h, bpp, rows

def png_write(path, w, h, bpp, rows):
    def chunk(t, b): return struct.pack(">I", len(b)) + t + b + struct.pack(">I", zlib.crc32(t + b) & 0xffffffff)
    raw = b"".join(b"\x00" + r for r in rows)
    ihdr = struct.pack(">IIBBBBB", w, h, 8, 6 if bpp == 4 else 2, 0, 0, 0)
    open(path, "wb").write(b"\x89PNG\r\n\x1a\n" + chunk(b"IHDR", ihdr) + chunk(b"IDAT", zlib.compress(raw, 9)) + chunk(b"IEND", b""))
